# Parleywise：基金营销材料合规初审

产品名 Parleywise（域名 parleywise.com）。本目录最早叫 MVP0，代码里的环境变量前缀 `HIAGENT_`、数据库文件名 `hiagent.db` 暂时沿用。

目标：验证「AI 初审能否在不增加漏审的前提下，把每份材料的审查时间缩短一半」。

## 文件
| 文件 | 内容 |
| --- | --- |
| `rules.json` | 30 条规则：《公开募集证券投资基金宣传推介材料管理暂行规定》第 4–15 条、《公开募集证券投资基金销售机构监督管理办法》第 24、45 条、《广告法》第 9 条。规则说明是转述，不是原文 |
| `golden/build_cases.py` → `golden/cases.jsonl` | 第一版黄金集：30 份合成样例（22 份违规、8 份合规，共 33 处预期问题）。基金名称和数字都是虚构的 |
| `review.py` | 审查脚本：关键词初筛 → 小模型初筛 → 强模型复核 → 校验器 → Markdown 报告；`--eval` 在黄金集上算召回率和准确率 |
| `interview_guide.md` | 访谈提纲 |

## 运行
```bash
# Python 环境统一用 uv 管理（无第三方依赖）
cp .env.example .env   # 填入 key 和两个模型名；.env 已在 .gitignore 中，不要提交

# 离线基线（只用关键词，不调模型）
uv run review.py --golden golden/cases.jsonl --eval --offline

# 经 LiteLLM 网关跑完整流程
uv run review.py --golden golden/cases.jsonl --eval

# 审单份材料
uv run review.py --text-file 某篇文案.txt
```
报告和 `eval.json` 写到 `out/`。只依赖 Python 3.10+ 标准库，由 uv 管理环境。网关如果没开 JSON 模式，脚本也会从回复里抽取 JSON。

## 多 Agent 协作实验（命令行）

可选开启两个独立初审角色并行、复核角色汇总的实验；沿用原有规则和校验器，工作台默认流水线不变。每篇最多多一次初审模型调用，会增加用量。两个角色使用相同的模型档位、材料和规则，只是提示侧重点不同；实验结果须与基线对照，不代表已提升质量。

```bash
uv run review.py --golden golden/cases.jsonl --eval --out out/baseline
uv run review.py --golden golden/cases.jsonl --eval --collaboration --out out/collaboration
uv run compare_evals.py out/baseline/eval.json out/collaboration/eval.json
```

可额外传入 `--trace-collaboration`，在每篇结果 JSON 的 `collaboration_trace` 中保存各角色原始意见，以便检查交接。意见可能含材料原文，默认关闭；仅在获授权时保存，并保护输出文件。

两次使用相同模型配置、规则、样例与 `HIAGENT_TODAY` 固定日期。评测结果记录输入、规则、脚本指纹与日期和模型别名；对照工具会拒绝指纹不一致、缺少清单或存在失败样例的结果。网关内别名指向的实际模型可能变化，仍需另行核对。失败样例不计入质量指标，任务退出码为非零；分母为零的指标为 null，不能视作 100%。网关未返回完整费用时 `cost_per_doc_usd` 为 null。历史评测没有新清单，需要重新评测才能使用自动对照。黄金集为短合成样例，结果不能证明真实业务效果，亦不能取代合规专家审查。涉及真实材料前先确认数据处理授权。

## 当前结果（2026-11-23）
- 离线关键词基线：召回率 33%（11/33），准确率 100%，没有误报。漏掉的主要是需要理解上下文的规则：业绩展示期间、比较基准、缺少声明、基金经理业绩、评级、股东背景等。
- v0.1 在线（deepseek-v4-flash-202605 初筛，deepseek-v4-pro 复核，2026-11-23）：召回率 94%（31/33），精确率 38%（误报 50），约 59 秒/份，平均约 7,300 token/份；网关未回传价格。漏报 R01 的原因是模型不知道当天日期；误报主要来自 R29 规则描述过宽，以及黄金集漏标。
- v0.2 改动：提示词注入当天日期（可用 HIAGENT_TODAY 固定）；收紧 R29/R22/R18/R07 描述；每条规则只出一条意见；黄金集补 4 处必须命中的 R02，并新增 acceptable（可接受的次要命中）；评测同时报 strict 与 lenient 两种精确率。acceptable 标注由 Claude 判断，需合规人员复核。

## 已知局限
- 规则依据的暂行规定文本来自第三方镜像，必须和证监会官网原文逐条核对，最好请合规人员一起核。
- 黄金集是我按规则合成的，比真实材料简单。下一步要换成真实公开材料和监管处罚案例。
- R28（注册完成前宣传）需要文本以外的信息，脚本不检查。
- 关键词「安全」「第一」这类词在真实文案里容易误报，需要靠模型复核压下去。
- Gemini 在境外，不要用它处理客户材料。

## 复核工作台（app/）
给合规人员用的网页：粘贴或上传材料 → AI 初审（复用 `review.py` 流水线）→ 逐条采纳/修改/驳回 → 补充 AI 漏报 → 导出报告；同时记录有效审查时长、驳回原因和人工补充问题，供度量页统计。设计说明见 `app/DESIGN.md`。

```bash
uv run python -m app.auth add <用户名> <姓名> --admin   # 第一次先建账号
./run.sh                                               # 打开 http://127.0.0.1:8000
```
数据存在 `app/data/hiagent.db`（已 gitignore）。上传支持 .txt/.md/.docx/.pdf（不含扫描件 OCR）。试点部署见 `app/DEPLOY.md`。

## 平台功能初版

工作台包含个人资料、修改口令、个人会话、手动个人记忆与 MCP 地址配置。注册默认关闭，管理员可按部署说明配置邀请码；当前所有注册用户共享合规材料，不支持机构或材料级隔离。

会话通过配置的 LiteLLM 网关调用初审档模型；消息和压缩摘要会发给该网关，使用前应确认数据处理授权。会话和个人记忆按账号隔离；项目记忆对本部署所有登录用户共享，由管理员维护。两类记忆均由用户手动维护，发送时逐条选择，仅在本次附带。压缩使用模型生成当前会话的摘要，保留全部原始消息；摘要可能有遗漏，可查看和修订。长会话按批压缩；单条消息或已有摘要超过处理上限时仍需人工处理。此原型只支持一个共享工作区，项目记忆尚无版本历史、审计或多项目隔离。模型请求在单进程内串行，尚无流式回复或生产级任务恢复。

MCP 目前仅保存用户填写的服务名称和地址，不连接服务、不验证可用性、不保存凭证，也不发现或调用工具；上线前仍需完成身份凭证、网络边界、权限和审批等能力。

“模型调用”展示启用记录后的网关请求尝试，包括用途、运行标识、请求与网关返回的模型、状态、耗时、token 和网关返回的费用。对话与压缩记录仅本人可见，合规审查记录在单机构工作区共享；删除对应会话或材料时删除相关记录。记录不保存提示词、回复、密钥或网关错误正文。历史调用无法补录，实时进行中的请求在结束后才出现；“网关已响应”不保证响应格式有效或任务成功，费用或用量未返回时显示未知。记录写入失败会在服务端输出警告，当前不提供完整审计保证。
