# hiagent MVP0：基金营销材料合规初审

目标：验证「AI 初审能否在不增加漏审的前提下，把每份材料的审查时间缩短一半」。

## 文件
| 文件 | 内容 |
| --- | --- |
| `rules.json` | 30 条规则：《公开募集证券投资基金宣传推介材料管理暂行规定》第 4–15 条、《公开募集证券投资基金销售机构监督管理办法》第 24、45 条、《广告法》第 9 条。规则说明是转述，不是原文 |
| `golden/build_cases.py` → `golden/cases.jsonl` | 第一版黄金集：30 份合成样例（22 份违规、8 份合规，共 33 处预期问题）。基金名称和数字都是虚构的 |
| `review.py` | 审查脚本：关键词初筛 → 小模型初筛 → 强模型复核 → 校验器 → Markdown 报告；`--eval` 在黄金集上算召回率和准确率 |
| `interview_guide.md` | 访谈提纲 |

## 运行
```bash
# Python 环境统一用 uv 管理（无第三方依赖）
cp .env.example .env   # 填入 key 和两个模型名；.env 已在 .gitignore 中，不要提交

# 离线基线（只用关键词，不调模型）
uv run review.py --golden golden/cases.jsonl --eval --offline

# 经 LiteLLM 网关跑完整流程
uv run review.py --golden golden/cases.jsonl --eval

# 审单份材料
uv run review.py --text-file 某篇文案.txt
```
报告和 `eval.json` 写到 `out/`。只依赖 Python 3.10+ 标准库，由 uv 管理环境。网关如果没开 JSON 模式，脚本也会从回复里抽取 JSON。

## 当前结果（2026-11-23）
- 离线关键词基线：召回率 33%（11/33），准确率 100%，没有误报。漏掉的主要是需要理解上下文的规则：业绩展示期间、比较基准、缺少声明、基金经理业绩、评级、股东背景等。
- v0.1 在线（deepseek-v4-flash-202605 初筛，deepseek-v4-pro 复核，2026-11-23）：召回率 94%（31/33），精确率 38%（误报 50），约 59 秒/份，平均约 7,300 token/份；网关未回传价格。漏报 R01 的原因是模型不知道当天日期；误报主要来自 R29 规则描述过宽，以及黄金集漏标。
- v0.2 改动：提示词注入当天日期（可用 HIAGENT_TODAY 固定）；收紧 R29/R22/R18/R07 描述；每条规则只出一条意见；黄金集补 4 处必须命中的 R02，并新增 acceptable（可接受的次要命中）；评测同时报 strict 与 lenient 两种精确率。acceptable 标注由 Claude 判断，需合规人员复核。

## 已知局限
- 规则依据的暂行规定文本来自第三方镜像，必须和证监会官网原文逐条核对，最好请合规人员一起核。
- 黄金集是我按规则合成的，比真实材料简单。下一步要换成真实公开材料和监管处罚案例。
- R28（注册完成前宣传）需要文本以外的信息，脚本不检查。
- 关键词「安全」「第一」这类词在真实文案里容易误报，需要靠模型复核压下去。
- Gemini 在境外，不要用它处理客户材料。
